# Google Classroom lesson bundle uploader

This directory is the version-controlled source for the companion Google Apps
Script web app. It accepts a Lesson Builder lesson bundle ZIP and posts its
PDF attachments as Google Classroom course-work material.

## Apps Script setup

1. Create or open the Apps Script project that hosts the uploader.
2. In **Services**, add the advanced **Google Classroom API** service.
3. In the manifest, ensure the project requests these OAuth scopes:

   - `https://www.googleapis.com/auth/classroom.courses.readonly`
   - `https://www.googleapis.com/auth/classroom.topics`
   - `https://www.googleapis.com/auth/classroom.courseworkmaterials`
   - `https://www.googleapis.com/auth/drive`
   - `https://www.googleapis.com/auth/userinfo.email`
4. Replace the Apps Script project's `Code.gs` and `Index.html` with the
   matching files in this directory.
5. Set `ALLOWED_SCRIPT_USER_EMAIL` in `Code.gs` to the teacher account that
   may use the uploader. Optionally set `DESTINATION_FOLDER_ID` to an existing
   Drive folder; leave it blank to use or create **Classroom Lesson Uploads**.
6. Deploy a new web-app version before deploying or using the Lesson Builder
   Preview that creates dual-PDF lesson bundles.

The existing uploader limit remains 25 MB for the ZIP and 20 Classroom
materials for a post.

## Bundle contract

Current bundles contain these entries:

- `<lesson>.pdf`: the saved lesson state, including saved reveals and annotations.
- `<lesson>-answers.pdf`: all answers, including the second Example, without annotations.
- `worksheets/*.pdf`: any worksheet and worksheet-answer attachments.
- `README.txt`, beginning with the exact line `Lesson Builder bundle format: 2`.

Classroom attachment order is the saved-state PDF first, the answers PDF second,
then worksheet PDFs in filename order. Root-PDF pairing is case-insensitive and
preserves original filenames. A lesson named `Title-answers` therefore contains
`Title-answers.pdf` and `Title-answers-answers.pdf`.

The uploader reads all ZIP entries before checking the README discriminator;
entry order cannot change bundle classification. A format-2 bundle must contain
both matching root PDFs. Two unrelated root PDFs or three root PDFs are rejected.
For transitional compatibility, a bundle without the format-2 marker may contain
one root PDF and at most one root PowerPoint file. The PowerPoint is ignored: it
is never uploaded or attached. Two correctly paired root PDFs are also accepted
without the marker.

## Compatibility smoke test

Before releasing the paired Lesson Builder change, use the deployed web app to
upload both of the following:

1. A previously downloaded legacy ZIP containing one root PDF and one root
   PowerPoint file.
2. A ZIP generated by the Lesson Builder Preview, containing the saved-state
   `<lesson>.pdf`, `<lesson>-answers.pdf`, the format-2 README, and zero or more
   PDFs in `worksheets/`.

Confirm the legacy upload shows its lesson PDF first, followed by worksheet PDFs
in filename order. Confirm the current upload shows the saved-state PDF first,
the answers PDF second, then worksheet PDFs in filename order. Check a title
ending in `-answers`, and confirm a format-2 bundle missing its answers PDF is
rejected whether README appears first or last. A legacy PowerPoint file is
accepted for transition compatibility but is not uploaded or attached.

Also smoke test course selection, existing and new topics, immediate posting,
scheduled posting, and the invalid-ZIP error path. If a Drive or Classroom
operation fails after files have been uploaded, the script cleans up the
uploaded files and lesson folder.
